# AI 圆桌 · 使用说明书

> 当前版本：**v1.2.0**
> 适用平台：Linux（源码 / deb 安装包）、Windows（安装包）、macOS（Apple Silicon 安装包）
> 一句话：**一个输入框，把同一个问题同时发给 8 个 AI 网页版，收齐回复后自动汇总成一份横向总结。**

---

## 一、简介

AI 圆桌是一个桌面小工具。你只需要在输入框里写一个问题，它会把问题**同时广播给 8 家 AI 网页版**，等各家陆续交卷后，再自动把八份答案揉成一份结构化综述。

**8 家参与模型：**

| | | | |
|---|---|---|---|
| 千问 | 豆包 | 元宝 | 智谱 |
| Kimi | DeepSeek | MiniMax | 文心 |

**核心特点**

- **不需要申请任何 API Key**：直接复用你浏览器里**已登录**的各家网页版账号，用网页自动化模拟真人提问、轮询抓取回复。零成本，开箱即用。
- **多家独立作答、交叉验证**：缓解单一模型的幻觉与视角偏差；共识留下、分歧标出，重要判断更踏实。
- **自动五段总结**：全部交卷后生成"主要共识 / 次要共识 / 分歧观点 / 个性观点 / 综合意见"，附录保留各家原文。
- **三种入口**：桌面 GUI、飞书机器人（可选）、本地 HTTP 接口（供 Agent / 脚本集成）。

> 说明：本说明书基于 v1.2.0 编写。相对早期版本，v1.2.0 新增了 Windows / macOS 安装包与 Linux deb 打包、单家补发（↻）、总结目录导航、自动总结开关等能力。

## 二、安装

### 方式一：安装包（推荐普通用户）

#### Linux（统信 UOS / Debian / Ubuntu，arm64）
已提供安装包 `dist/ai-roundtable_1.2.0_arm64.deb`，双击安装或命令行安装：

```bash
sudo dpkg -i dist/ai-roundtable_1.2.0_arm64.deb
# 依赖缺失时执行：
sudo apt-get install -f
```

安装后从应用菜单启动「AI 圆桌」即可。

#### Windows（x64）
运行 `scripts/build-windows.sh` 对应的构建流程生成 `AI 圆桌-Setup-x64.exe`（或直接获取发布包），双击按向导安装。
开机自启脚本随安装包附带（`setup-autostart-windows.bat`）。

#### macOS（Apple Silicon）
运行 `scripts/build-macos.sh` 生成 `.dmg`，拖入「应用程序」即可。
开机自启脚本随安装包附带（`setup-autostart-macos.sh`）。

### 方式二：源码运行（适合开发者 / 自定义）

环境要求：**Node.js 18+**、**图形会话（Linux 需 X11）**。Electron 需要窗口与 webview 真实渲染，**无头服务器不适用**。

```bash
git clone https://github.com/sundanan/ai-roundtable.git
cd ai-roundtable
bash install.sh      # 检查环境 → npm install → 生成 .env 模板
npm start            # 启动应用
```

### 可选依赖
- **pandoc**：飞书 / HTTP 渠道的总结 docx 附件依赖它；未安装时自动回退为纯文本，不影响桌面端核心功能。

### 启动与常驻
- 关闭窗口不会退出，应用**隐藏到系统托盘**常驻；托盘菜单可「显示主窗口 / 退出」。
- 推荐用 systemd 用户服务运行（崩溃 5 秒自动重启）：

```bash
systemctl --user start ai-roundtable
# 日常管理：status | restart | stop
```

- 也可手动：`bash service.sh`（日志写入 `~/ai-roundtable-service.log`，超 20MB 自动截断）。

## 三、界面总览

启动后主窗口分三层：

1. **顶部输入区**：`＋` 清空按钮（30px 宽竖条，整条可点）、问题输入框、右侧按钮组（**发送 / 总结 / 设置 / 历史**）。
2. **模型栏**：显示「已选 8/8」计数与 8 个模型按钮（**单击任一按钮 = 全屏打开该家网页**，用于登录 / 查看 / 补发）。是否参与圆桌在「设置」里勾选。
3. **输出区**（模型栏与输出区之间有一条**可上下拖拽的横向分隔条**，可调整两块区域的高度分配）：
   - 左侧：各家回复进度与内容（每行一家，固定显示该家回复**首行预览**，单击行可跳转总结附录中该家原文；行尾 `↻` 可单家重发）；
   - 右侧：**总结面板**（五段结构 + 目录跳转 + 复制 / 存为 MD）。

**状态胶囊**：每行右侧实时显示 `待发送 → 发送中 → 生成中… Ns → 已完成 ✓`；超过 90 秒未交卷显示「仍在生成 + 秒数」，避免误判卡死；失败时**整行标红**并显示显眼的红色「↻ 重发」按钮。

另有「设置」弹窗、「历史」弹窗，以及点击模型按钮后出现的**全屏网页浮层**（用来登录各家账号）。

## 四、设置与各页面登录

### 4.1 登录总览
AI 圆桌**不申请任何 API Key**，而是复用你各家**网页版**已登录的账号。登录态通过持久化分区保存，**重启不丢**。你需要登录两类账号：

- **8 家回答账号**：千问、豆包、元宝、智谱、Kimi、DeepSeek、MiniMax、文心；
- **1 个总结账号**：DeepSeek「第二账号」（用于生成总结，与你的回答账号隔离，避免互相污染）。

### 4.2 登录 8 家 AI 网页账号
1. 在模型栏找到对应模型按钮（如「豆包」「DeepSeek」）。
2. **单击该按钮**，弹出该家的全屏网页浮层。
3. 在浮层内像平时一样登录该 AI 网页版（扫码 / 手机号 / 账号密码均可）。
4. 登录成功后，点击浮层右上角关闭（×），回到主窗口。
5. 对 8 家**逐一重复**上述步骤，每家登录一次即可。

> 提示：登录态会持久保存，之后一般无需重复登录。某家账号掉线 / 失效时，同样**单击该家按钮全屏重新登录一次**即可。

### 4.3 登录总结用 DeepSeek 第二账号
总结默认走「网页总结」，由 DeepSeek 第二账号生成。首次使用时需登录：

- 点右侧总结面板的标题 **「📋 总结」**，会全屏展开 DeepSeek 总结账号页面——在此**手动登录第二个 DeepSeek 账号**（只登录、不触发总结）；
- 或直接点「总结」按钮，系统也会全屏展开该页面，首次需先登录。
- 之后每次总结自动从首页开新会话，不污染任何回答会话。

> 若你不想用第二账号，可在「设置」切换为 **API 总结**（见 4.4），无需额外登录。

### 4.4 总结方式设置
打开「设置」弹窗（右上角 **设置** 按钮）：

- **网页总结 · DeepSeek 第二账号（默认，免费，免 API Key）**：如上，首次登录第二账号即可。
- **API 总结 · OpenAI 兼容接口（备选）**：勾选后填写：
  - Base URL（如 `https://api.deepseek.com/v1`）
  - API Key
  - 模型名（如 `deepseek-chat`）
  - 配置仅保存在本机（localStorage）。

### 4.5 参与各家与发送快捷键
在「设置」弹窗的「参与各家」区域：

- 勾选 / 取消勾选，决定本轮哪些模型参与（顶部「已选 N/8」实时更新）；
- 「全选 / 清空」可一键切换；
- **发送快捷键**可选：
  - `Ctrl+Enter` 发送（Enter 换行）——默认；
  - `Enter` 发送（Shift+Enter 换行）。

### 4.6 自动总结开关
「设置」中可勾选 **「全部交卷后自动总结（桌面端）」**。开启后，各家全部回复完毕会自动生成总结，无需手动点「总结」。

### 4.7 飞书入口登录（可选）
如需在飞书私聊机器人触发圆桌：

1. 在 [飞书开放平台](https://open.feishu.cn) 创建企业自建应用，开通机器人能力；
2. 事件订阅选「长连接」模式，订阅 `im.message.receive_v1`；
3. 把 App ID / App Secret 填入项目根目录 `.env`（参照 `.env.example`）；
4. （可选）在 `.env` 配置 `FEISHU_ALLOW_CHAT_IDS`（逗号分隔 chat_id 白名单，防无关会话消耗额度）；群消息无论是否在白名单，都必须 **@机器人** 才触发。

> 不配置飞书完全不影响桌面端与 HTTP 接口。

## 五、输入问题

1. 在顶部**输入框**写入你的问题（支持多行）。
2. 确认模型栏中**参与各家**已按需要勾选（默认全 8 家；子集可在「设置」里调整）。
3. 发送：
   - 默认 `Ctrl+Enter` 发送（或在「设置」改为 `Enter` 发送）；
   - 也可直接点右侧 **发送** 按钮。
4. 发送后**输入框保留问题文本**，方便继续追问；要开一个全新问题，先点 `＋` 清空输入框。
5. 发送瞬间，问题被广播给所有参与模型，模型栏各家状态灯亮起「生成中」，输出区左侧逐家出现回复预览与进度。

**补发 / 重发**
- 某家失败或答案不理想：点该行行尾的 **`↻`** 按钮，仅重发该家，不影响其他家、不清空其他家的回复。
- 行尾 `↻` 在该家失败时放大为「↻ 重发」，提示更醒目。

## 六、查看总结

当各家全部交卷（或到达轮次上限）后：

- 若已开启「自动总结」，总结会自动生成；
- 否则点右侧 **总结** 按钮（有回复后才可点击）生成。

**总结面板内容**
- 正文按五段结构排版：
  1. 一、主要共识
  2. 二、次要共识
  3. 三、分歧观点
  4. 四、个性观点
  5. 五、综合意见
- 左侧**目录标签**为五段固定标签 + 「各家意见」可展开二级标签（点击展开 8 家，逐家跳转附录原文，带品牌色圆点）；滚动正文时目录会**自动高亮当前阅读位置**（scroll-spy）。
- 点左侧某家名称行，可跳转总结附录中对应家的原文。
- 未生成总结时，面板显示**五段结构的骨架屏预览**，目录标签同样可见（占位，不可点击）。
- 面板顶部按钮：
  - **复制**：复制总结全文；
  - **存为 MD**：把总结保存为 Markdown 文件；
  - **↑ 顶部**：回到总结开头。

> 总结依赖配置：API 模式下未配总结 LLM 时总结会报错（各家回复照常）；未配置时直接用默认的网页总结即可。

## 七、查看历史

所有轮次自动留档（最多 200 条）。

**桌面端**
1. 点右上角 **历史** 按钮，打开历史弹窗。
2. 左侧为历史列表（问题 + 时间 + 参与家数）。
3. 顶部搜索框可按**问题关键词**过滤；`⟳` 刷新、`×` 清空搜索词。
4. 点击某条记录，右侧显示完整详情：**五段总结 + 各家回复原文**。

**通过 HTTP 接口（进阶 / 集成）**
服务监听 `127.0.0.1:8765`，仅本机可访问：

```bash
# 历史列表（limit 条数，q 关键词）
curl "http://127.0.0.1:8765/history?limit=20&q=武汉"

# 单条完整内容
curl "http://127.0.0.1:8765/history/item?id=某条ID"
```

## 八、常见故障 Q&A

**Q1：某家一直抓不到回复 / 显示空白？**
多半是该家网页登录态失效，或该家网站改版。先**单击该家模型按钮全屏重新登录一次**；若是网站改版导致的选择器失效，需等待维护者更新 `src/adapters.js`（普通用户可暂时手动在全屏页发送 / 补发）。

**Q2：点「总结」提示未登录 / 发送失败？**
网页总结首次使用需登录 **DeepSeek 第二账号**。点总结面板标题 **「📋 总结」** 全屏展开该页面，手动登录第二账号后再点「总结」。

**Q3：总结一直转圈 / 超时？**
深度思考、联网研究类回答耗时较长，可能超过单轮上限（默认约 7 分钟）。请耐心等待；若频繁超时，可改用 API 总结，或确认网络通畅。

**Q4：某家一直「生成中」不交卷？**
该家本身较慢或网站有变动。可点行尾 **`↻`** 重发，或单击该家按钮全屏手动发送 / 查看真实状态。

**Q5：API 总结报错？**
检查「设置」里 API 总结的 Base URL / API Key / 模型名是否填对；或直接切回「网页总结」。

**Q6：飞书机器人没反应？**
检查 `.env` 的 App ID / Secret 是否正确；确认消息来自白名单会话（或群里已 **@机器人**）；不配置飞书不影响桌面端。

**Q7：窗口关了，程序还在吗？能再打开吗？**
关窗只是隐藏到**系统托盘**，程序仍在运行。从托盘菜单选「显示主窗口」即可；托盘菜单也可「退出」。

**Q8：重复发送提示 busy？**
服务同一时间只跑一轮（单轮串行）。请等当前轮次完成后再发下一个问题。

**Q9：程序卡死 / 无响应？**
用 systemd 用户服务运行时进程崩溃会自动重启；也可 `bash service.sh` 手动拉起，或完全退出后重新启动应用。

**Q10：启动报错「需要显示环境 / Electron 无法渲染」？**
Electron 必须运行在图形会话中（Linux 需 X11）。无头服务器、纯命令行环境无法使用桌面 GUI。

**Q11：MiniMax 那一家经常失败？**
可能该账号**积分余额不足**。留意各家账号额度，额度耗尽时该家会失败。

**Q12：抓到的是上一轮的答案？**
引擎已内置「发送前记录基线、抓到旧内容则判失败」的防误判机制，正常情况下不会拿旧回复充数。若偶发，点行尾 `↻` 补发即可（补发主要用于救治失败 / 垃圾答案）。

**Q13：某家反复发送失败，页面弹出滑块验证码？**
千问等站点会对自动化操作触发人机验证，合成操作会被风控拒绝。**单击该家按钮全屏打开，手动完成一次滑块验证**，再点「↻ 重发」即可恢复。

**Q14：历史记录存在哪里？会丢吗？**
保存在本机用户数据目录（Electron userData），最多 200 条。重装系统或清除用户数据才会丢失；重要总结建议用「存为 MD」另行保存。

**Q15：HTTP 接口调用很慢 / 超时？**
一轮圆桌耗时约 1–7 分钟（取决于最慢的一家与总结耗时），客户端请给足超时（示例用 `--max-time 460`）。同一时间只跑一轮，并发请求返回 busy。

**Q16：启动报 GPU 相关错误 / 界面偶发异常？**
启动命令已带 `--disable-gpu --ozone-platform=x11`；systemd 服务配置了崩溃 5 秒后自动重启，偶发 GPU FATAL 无需处理。界面元素错位等异常先 `systemctl --user restart ai-roundtable`，仍异常请截图反馈。

## 九、重要提醒（必读）

- **合规**：本项目以自动化方式操作**消费级网页版** AI，可能触碰各家服务条款（ToS）。仅供**个人学习研究**使用，请自行评估风险、控制频率、**勿用于商业化批量抓取**。使用本项目产生的一切后果由使用者自行承担。
- **安全**：HTTP 接口仅绑定 `127.0.0.1`，不暴露到网络；飞书凭证只存 `.env`（已忽略进版本库），源码不含硬编码密钥；webview 外链一律经主进程白名单校验后交系统浏览器打开。
- **已知限制**：强依赖各家网页结构，改版即需适配（此类方案固有代价）；深度思考 / 联网研究超长回答可能超出单轮上限；单轮串行，一次只跑一个提问。
