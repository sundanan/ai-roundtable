# AI 圆桌 · 使用说明书

> 当前版本：**v1.4.0**
> 适用平台：Linux（源码 / deb 安装包）、Windows（NSIS 安装包 + 绿色版）、macOS（Apple Silicon 安装包）
> 一句话：**一个输入框，把同一个问题同时发给 9 个 AI 网页版，收齐回复后自动汇总成一份横向总结。**

> **v1.4.0 更新**：① **首次运行向导**（逐家登录检测 → 总结方式配置 → 使用提示，可在「设置」重开）；② **总结模型扩充到全部 9 家**（按附件直传能力标注，自动回退文本模式）；③ **历史记录导出 MD/PDF、删除、纵向章节目录**；④ **界面合并**：原上部模型按钮栏并入回复行行头（家名单击全屏、▸ 展开全文、参与置灰）；⑤ 等待时长放宽（单家看门狗 7 分钟 / 微信轮次 15 分钟）；⑥ 微信发起的问题同步显示到输入框、「＋」一键复位待命、设置重叠提醒去重。

> **v1.3.0 更新**：相对 v1.2.0，三端官方构建全部就绪并发布正式安装包 —— Linux deb（arm64，统信/深度/Ubuntu/Debian 适配）、Windows（NSIS 安装包 + 绿色版 zip 解压即跑）、macOS（Apple Silicon zip 拖入应用程序）。本手册同步更新到 v1.3.0；功能、界面、设置、Q&A 与 v1.2.0 基本一致。

## 一、简介

AI 圆桌是一个桌面小工具。你只需要在输入框里写一个问题，它会把问题**同时广播给 9 家 AI 网页版**，等各家陆续交卷后，再自动把九份答案揉成一份结构化综述。

**9 家参与模型：**

| | | | |
|---|---|---|---|
| 千问 | 豆包 | 元宝 | 智谱 |
| Kimi | DeepSeek | MiniMax | 文心 | MiMo |

**核心特点**

- **不需要申请任何 API Key**：直接复用你浏览器里**已登录**的各家网页版账号，用网页自动化模拟真人提问、轮询抓取回复。零成本，开箱即用。
- **多家独立作答、交叉验证**：缓解单一模型的幻觉与视角偏差；共识留下、分歧标出，重要判断更踏实。
- **自动五段总结**：全部交卷后生成"主要共识 / 次要共识 / 分歧观点 / 个性观点 / 综合意见"，附录保留各家原文。
- **两种入口**：桌面 GUI、本地 HTTP 接口（供 Agent / 脚本集成）。

> 说明：v1.2.0 引入了 Windows / macOS 安装包与 Linux deb 打包、单家补发（↻）、总结目录导航、自动总结开关等能力。v1.3.0 进一步把三端构建都做成了正式可发布的安装包/绿色版。

## 二、安装

### 方式一：安装包（推荐普通用户）

#### Linux（统信 UOS / Debian / Ubuntu，arm64）
已提供安装包 `dist/ai-roundtable_1.3.0_arm64.deb`，双击安装或命令行安装：

```bash
sudo dpkg -i dist/ai-roundtable_1.3.0_arm64.deb
# 依赖缺失时执行：
sudo apt-get install -f
```

安装后从应用菜单启动「AI 圆桌」即可。

#### Windows（x64）
v1.3.0 提供两种发布包，按需二选一：

- **NSIS 安装包**（`AI圆桌-1.3.0-win-x64.exe`）：双击按向导安装，可选附带 `setup-autostart-windows.bat` 开机自启；
- **绿色版 zip**（`AI圆桌-1.3.0-win-x64-绿色版.zip`）：解压到任意目录，双击目录里的 `AI圆桌.exe` 直接运行，**不写注册表、不装服务**，适合便携/U 盘使用。

构建命令：`npm run dist:win`（NSIS）/ `scripts/build-windows.sh`（绿色版）。

#### macOS（Apple Silicon）
v1.3.0 发布包：`AI圆桌-1.3.0-macos-arm64.zip`，下载后解压，把 `AI 圆桌.app` 拖入「应用程序」即可。
构建命令：`npm run dist:mac`（或 `scripts/build-macos.sh`）。开机自启脚本随安装包附带（`setup-autostart-macos.sh`）。

### 方式二：源码运行（适合开发者 / 自定义）

环境要求：**Node.js 18+**、**图形会话（Linux 需 X11）**。Electron 需要窗口与 webview 真实渲染，**无头服务器不适用**。

```bash
git clone https://github.com/sundanan/ai-roundtable.git
cd ai-roundtable
bash install.sh      # 检查环境 → npm install → 生成 .env 模板
npm start            # 启动应用
```

### 可选依赖
- **pandoc**：HTTP 渠道的总结 docx 附件依赖它；未安装时自动回退为纯文本，不影响桌面端核心功能。

### 启动与常驻
- **关闭窗口默认退出**（微信/HTTP 服务随之停止）；可在「设置 → 关闭窗口时」切换为「最小化到托盘」常驻，托盘菜单可「显示主窗口 / 退出」。
- 推荐用 systemd 用户服务运行（崩溃 5 秒自动重启）：

```bash
systemctl --user start ai-roundtable
# 日常管理：status | restart | stop
```

- 也可手动：`bash service.sh`（日志写入 `~/ai-roundtable-service.log`，超 20MB 自动截断）。

## 三、界面总览

启动后主窗口分两层（原第二层"模型按钮栏"已并入回复行，**每行即该家唯一入口**）：

1. **顶部输入区**：`＋` 清空按钮（30px 宽竖条，整条可点）、问题输入框、右侧按钮组（**发送 / 总结 / 设置 / 历史**）。
2. **输出区**（输入区与输出区之间有一条**可上下拖拽的横向分隔条**，可调整输入框高度）：
   - 进度行：轮次进度文本 + 进度条 + 右侧「**已选 N/9**」计数（点击打开「设置」调整参与各家）；
   - 左侧：各家回复行（每行一家，行高按剩余空间均分、不出滚动条）。行头依次为：**加载灯**（橙=加载中、红=失败，异常时才显示）→ **logo** → **家名** → 状态胶囊 → `🛡 去验证` → `↻` 重发 → `▸` 展开开关；**单击行体或行头家名 = 全屏打开该家网页**（用于登录 / 查看 / 补发）；**点 `▸` 展开 / 收起该家全文**（Markdown 渲染），展开区内有「在总结附录中查看」次级入口；未勾选参与的行整行置灰；
   - 右侧：**总结面板**（五段结构 + 目录跳转 + 复制 / 存为 MD）。

**状态胶囊**：每行右侧实时显示 `待发送 → 发送中 → 生成中… Ns → 已完成 ✓`；超过 90 秒未交卷显示「仍在生成 + 秒数」，避免误判卡死；失败时**整行标红**并显示显眼的红色「↻ 重发」按钮。

另有「设置」弹窗、「历史」弹窗，以及单击行首家名后出现的**全屏网页浮层**（用来登录各家账号）。

## 四、设置与各页面登录

> **首次使用向导**：第一次启动会自动弹出「新手引导」——欢迎介绍 → **逐家检测并引导登录 9 个模型**（每家显示 ✓已登录/✗未登录，点「去登录」全屏登录，返回自动刷新）→ **选择总结方式**（网页总结登录总结账号 / API 填 Key，当场保存）→ 使用提示。可随时跳过；之后在「设置」弹窗底部点「新手引导」可重新打开。

### 4.1 登录总览
AI 圆桌**不申请任何 API Key**，而是复用你各家**网页版**已登录的账号。登录态通过持久化分区保存，**重启不丢**。你需要登录两类账号：

- **9 家回答账号**：千问、豆包、元宝、智谱、Kimi、DeepSeek、MiniMax、文心、MiMo（小米账号登录）；
- **1 个总结账号**：总结专用账号（默认 DeepSeek「第二账号」，可在「设置」改用其他家；用于生成总结，与你的回答账号隔离，避免互相污染）。

### 4.2 登录 9 家 AI 网页账号
1. 在回复区找到对应的家行（如「豆包」「DeepSeek」）。
2. **单击该行行头的家名 / logo**，弹出该家的全屏网页浮层。
3. 在浮层内像平时一样登录该 AI 网页版（扫码 / 手机号 / 账号密码均可）。
4. 登录成功后，点击浮层右上角关闭（×），回到主窗口。
5. 对 9 家**逐一重复**上述步骤，每家登录一次即可。

> 提示：登录态会持久保存，之后一般无需重复登录。某家账号掉线 / 失效时，同样**单击该家行首家名全屏重新登录一次**即可。

### 4.3 登录总结用 DeepSeek 第二账号
总结默认走「网页总结」，由 DeepSeek 第二账号生成。首次使用时需登录：

- 点右侧总结面板的标题 **「📋 总结」**，会全屏展开 DeepSeek 总结账号页面——在此**手动登录第二个 DeepSeek 账号**（只登录、不触发总结）；
- 或直接点「总结」按钮，系统也会全屏展开该页面，首次需先登录。
- 之后每次总结自动从首页开新会话，不污染任何回答会话。

> 若你不想用第二账号，可在「设置」切换为 **API 总结**（见 4.4），无需额外登录。

### 4.4 总结方式设置
打开「设置」弹窗（右上角 **设置** 按钮）：

- **网页总结 · 第二账号（默认，免费，免 API Key）**：如上，首次登录总结专用账号即可。「网页总结」同一行的「**总结模型**」下拉可选择由哪一家生成总结——**全部 9 家均可选**，按附件直传能力标注（DeepSeek / MiMo 实测支持附件直传、完整输入 9 家原文；豆包文件框支持 docx/md；其余家附件上传失败时自动回退文本模式、每家截断 2000 字）；若所选总结模型同时勾选了参与回答，保存时会弹窗提醒双账号的价值（上下文隔离 / 风控额度独立 / 可并行），可「仍这样保存」或「返回调整」——**该提醒只在重叠组合发生变化时出现一次**，共用一个账号也可以。
- **API 总结 · OpenAI 兼容接口（备选）**：勾选后默认已指向**智谱免费模型 GLM-4.7-Flash**（Base URL `https://open.bigmodel.cn/api/paas/v4`、模型名 `glm-4.7-flash`），只需填你自己的 API Key；也可改填任意 OpenAI 兼容接口。
  - 配置仅保存在本机（localStorage）。

### 4.5 参与各家与发送快捷键
在「设置」弹窗的「参与各家」区域：

- 勾选 / 取消勾选，决定本轮哪些模型参与（进度行右侧「已选 N/9」实时更新，未选的家行在回复区置灰）；
- 「全选 / 清空」可一键切换；
- **界面主题**：跟随系统（默认）/ 深色 / 浅色。
- **关闭窗口时**：退出程序（默认，关窗即结束应用与微信/HTTP 服务）/ 最小化到托盘（关窗隐藏到托盘，服务保持常驻，托盘菜单可「显示主窗口 / 退出」）。
2. **发送快捷键**可选：
  - `Ctrl+Enter` 发送（Enter 换行）——默认；
  - `Enter` 发送（Shift+Enter 换行）。

### 4.6 自动总结开关
「设置」中 **「全部交卷后自动总结（桌面端）」** 默认开启：各家全部回复完毕会自动生成总结，无需手动点「总结」。另外**超过 3 家交卷后**「总结」按钮即可点击，支持提前总结（不等慢家）。

## 五、输入问题

1. 在顶部**输入框**写入你的问题（支持多行）。
2. 确认**参与各家**已按需要勾选（默认全 9 家；进度行右侧「已选 N/9」计数或「设置」里查看调整）。
3. 发送：
   - 默认 `Ctrl+Enter` 发送（或在「设置」改为 `Enter` 发送）；
   - 也可直接点右侧 **发送** 按钮。
4. 发送后**输入框保留问题文本**，方便继续追问；要开一个全新问题，先点 `＋`——除清空输入框外，**回复行、进度条与总结面板会一并复位待命**（轮次或总结进行中只清输入框，不打断结果）。
5. 微信 / HTTP 接口（`POST /ask`）发起的轮次，**问题文本会同步显示到输入框**，方便在桌面端跟进进度。
6. 发送瞬间，问题被广播给所有参与模型，右上角「发送」按钮**原地变为红色「⏹ 停止」**；进度行实时显示「已完成 x/y」，各家回复行亮起「生成中」，左侧逐家出现回复预览与进度。
7. 轮次进行中点击红色 **「⏹ 停止」** 即中断本轮等待与轮询（已交卷的回复保留，未完的行标「⏹ 已停止」，可点 `↻` 重发）。

**补发 / 重发**
- 某家失败或答案不理想：点该行行尾的 **`↻`** 按钮，仅重发该家，不影响其他家、不清空其他家的回复。
- 行尾 `↻` 在该家失败时放大为「↻ 重发」，提示更醒目。
- 失败按「该做什么」分三档显示：**橙边 🛡 需人工验证**（页面停在登录/验证，行内出现「🛡 去验证」按钮，全屏处理完回来自动补发）、**蓝边 ⏱ 超时可重试**（点 ↻ 即可）、**红边 ⚠ 发送失败**（点 ↻ 重发或全屏手动发送）。

## 六、查看总结

当各家全部交卷（或到达轮次上限）后：

- 若已开启「自动总结」，总结会自动生成；
- 否则点右侧 **总结** 按钮（有回复后才可点击）生成。

**总结面板内容**
- 正文按五段结构排版：
  1. 一、主要共识
  2. 二、次要共识
  3. 三、分歧观点
  4. 四、个性观点
  5. 五、综合意见
- 左侧**目录标签**为五段固定标签 + 「各家意见」可展开二级标签（点击展开 9 家，逐家跳转附录原文，带品牌色圆点）；滚动正文时目录会**自动高亮当前阅读位置**（scroll-spy）。
- 点左侧某家名称行，可跳转总结附录中对应家的原文。
- 未生成总结时，面板显示**五段结构的紧凑全篇示意**（一、~五、与附录逐行排列），目录标签同样可见（占位，不可点击）。
- 面板顶部按钮：
  - **复制**：复制总结全文；
  - **存为 MD**：把总结保存为 Markdown 文件；
  - **↑ 顶部**：回到总结开头。

> 总结依赖配置：API 模式下未配总结 LLM 时总结会报错（各家回复照常）；未配置时直接用默认的网页总结即可。

## 七、查看历史

所有轮次自动留档（最多 200 条）。

**桌面端**
1. 点右上角 **历史** 按钮，打开历史弹窗。
2. 左侧为历史列表（问题 + 时间 + 参与家数）。
3. 顶部搜索框可按**问题关键词**过滤；`⟳` 刷新、`×` 清空搜索词。
4. 点击某条记录，右侧显示完整详情：**五段总结 + 各家回复原文**。详情左侧有**纵向章节目录**（与主界面总结面板同构：主要共识~综合意见固定标签 + 可展开的「各家意见」分组，各家带品牌色点），点击跳转对应位置，滚动时自动高亮当前章节；无总结的老记录退化为各家跳转标签。
5. 详情顶部工具条可 **「导出 MD」/「导出 PDF」** 当前记录（长文滚动时始终可见）；导出正文优先用总结全文（含各家原文附录），总结缺失时自动以各家回复代替。
6. **「删除」** 当前记录：两步确认（按钮变红「确认删除？」后 3 秒内再点执行），删除不可恢复；记录附带的总结 docx 附件会一并清理。

**通过 HTTP 接口（进阶 / 集成）**
服务监听 `127.0.0.1:8765`，仅本机可访问：

```bash
# 历史列表（limit 条数，q 关键词）
curl "http://127.0.0.1:8765/history?limit=20&q=武汉"

# 单条完整内容
curl "http://127.0.0.1:8765/history/item?id=某条ID"
```

## 八、常见故障 Q&A

**Q1：某家一直抓不到回复 / 显示空白？**
多半是该家网页登录态失效，或该家网站改版。先**单击该家行首家名全屏重新登录一次**；若是网站改版导致的选择器失效，需等待维护者更新 `src/adapters.js`（普通用户可暂时手动在全屏页发送 / 补发）。

**Q2：点「总结」提示未登录 / 发送失败？**
网页总结首次使用需登录**总结专用账号**（默认 DeepSeek，可在设置中改选其他家）。点总结面板标题 **「📋 总结」** 全屏展开该页面，手动登录后再点「总结」。

**Q3：总结一直转圈 / 超时？**
深度思考、联网研究类回答耗时较长，可能超过单轮上限（默认约 15 分钟）。请耐心等待；若频繁超时，可改用 API 总结，或确认网络通畅。

**Q4：某家一直「生成中」不交卷？**
该家本身较慢或网站有变动。可点行尾 **`↻`** 重发，或单击该家行首家名全屏手动发送 / 查看真实状态。

**Q5：API 总结报错？**
检查「设置」里 API 总结的 Base URL / API Key / 模型名是否填对；或直接切回「网页总结」。

**Q6：HTTP 接口调用很慢 / 超时？**
一轮圆桌耗时约 1–15 分钟（取决于最慢的一家与总结耗时），客户端请给足超时（示例用 `--max-time 960`）。同一时间只跑一轮，并发请求会返回 busy。

**Q7：窗口关了，程序还在吗？能再打开吗？**
默认**关窗即退出**（微信/HTTP 服务随之停止，重新打开应用即可恢复）；若在「设置 → 关闭窗口时」切换为「最小化到托盘」，则关窗只是隐藏到**系统托盘**，程序仍在运行——从托盘菜单选「显示主窗口」找回，或「退出」。

**Q8：重复发送提示 busy？**
服务同一时间只跑一轮（单轮串行）。请等当前轮次完成后再发下一个问题。

**Q9：程序卡死 / 无响应？**
用 systemd 用户服务运行时进程崩溃会自动重启；也可 `bash service.sh` 手动拉起，或完全退出后重新启动应用。

**Q10：启动报错「需要显示环境 / Electron 无法渲染」？**
Electron 必须运行在图形会话中（Linux 需 X11）。无头服务器、纯命令行环境无法使用桌面 GUI。

**Q11：MiniMax 那一家经常失败？**
可能该账号**积分余额不足**。留意各家账号额度，额度耗尽时该家会失败。

**Q12：抓到的是上一轮的答案？**
引擎已内置「发送前记录基线、抓到旧内容则判失败」的防误判机制，正常情况下不会拿旧回复充数。若偶发，点行尾 `↻` 补发即可（补发主要用于救治失败 / 垃圾答案）。

**Q13：某家反复发送失败，页面弹出滑块验证码？**
千问等站点会对自动化操作触发人机验证，合成操作会被风控拒绝。**单击该家行首家名全屏打开，手动完成一次滑块验证**，再点「↻ 重发」即可恢复。

**Q14：历史记录存在哪里？会丢吗？**
保存在本机用户数据目录（Electron userData），最多 200 条。重装系统或清除用户数据才会丢失；重要总结建议用「存为 MD」另行保存。

**Q15：HTTP 接口调用很慢 / 超时？**
一轮圆桌耗时约 1–15 分钟（取决于最慢的一家与总结耗时），客户端请给足超时（示例用 `--max-time 960`）。同一时间只跑一轮，并发请求返回 busy。

**Q16：启动报 GPU 相关错误 / 界面偶发异常？**
启动命令已带 `--disable-gpu --ozone-platform=x11`；systemd 服务配置了崩溃 5 秒后自动重启，偶发 GPU FATAL 无需处理。界面元素错位等异常先 `systemctl --user restart ai-roundtable`，仍异常请截图反馈。
